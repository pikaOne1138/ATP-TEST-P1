## 使用者已定案的做法

- **不部署**：只做本機預覽與截圖。線上預覽、發布相關項目一律標「受阻」，不標通過。
- **一次只做一種網站類型**，做完再換。
- **資料包腳本要先審查，再由主對話執行。** 建站子代理的環境會擋下「執行下載來的程式」。知識型用到的腳本已審查過：只寫入指定資料夾與暫存區、無對外連線、只呼叫 node／git／npm。
- **省用量**：建站工作由主對話直接做。子代理只用來模擬學員，每個只做一件明確的事，用完就丟，不來回多輪。先不要開子代理，有需要先問使用者。
- **給 ATP 的建議只記錄，不修改 ATP 的任何東西**（正式站、資料包、Skill 都不動）。
- 不得使用 ATP 的開發倉庫補資料；一切以正式站交付的內容為準。
- 不開 PR，除非使用者要求。

## 環境注意事項

- 測試時的本機工作資料夾（`/home/user/atp-run2/`，含下載的資料包、候選工作區、截圖腳本）是暫時性的，新對話裡不會存在。
- 要繼續操作測試網站：取出 `sim/run2-knowledge` 分支到另一個資料夾，`npm ci` 後 `npm run build`。
- 要重新取得資料包：從正式站 `/guide/` 下載「AI 建站資料包」，解壓到獨立的空資料夾。測試時的版本是 `sourceCommit de9b78c9…`。
- 專案自帶的 `npm run qa:responsive` 在這個環境跑不起來（Playwright 版本與預裝瀏覽器不合）。截圖請用全域的 Playwright，指定 `executablePath: '/opt/pw-browsers/chromium'`，腳本放在專案資料夾外。
